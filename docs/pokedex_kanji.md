# 図鑑説明文のかな／漢字切り替え

図鑑の説明文だけを、既存のかな本文と、後世代の公式日本語表記を参照した漢字本文から選びます。ゲーム内の言語設定ではなく、**コンパイル時の設定**です。既存のかな本文を漢字へ機械変換する機能ではありません。

## 有効にする

初期設定はかな版です。かな版には外部のテキスト取得は不要で、従来どおりビルドできます。

漢字版を使う場合、最初にプロジェクトルートで次を実行してください。ここだけインターネット接続が必要です。

```sh
python3 tools/pokedex_kanji.py fetch
```

取得先は `build/reference/poke-corpus/` です。固定リビジョンのファイルを取得し、manifestのSHA256と照合します。通常の `make` はネットワークへアクセスしません。キャッシュがない・破損している場合、必要なファイル名と取得コマンドを表示して停止します。

継続して使う設定は `include/config/pokemon.h` で変更します。

```c
#ifndef P_POKEDEX_TEXT_STYLE
#define P_POKEDEX_TEXT_STYLE POKEDEX_TEXT_KANJI
#endif
```

| 値 | 動作 |
| --- | --- |
| `POKEDEX_TEXT_KANA` / `0` | 従来のかな説明。初期設定 |
| `POKEDEX_TEXT_KANJI` / `1` | 最新作品優先の漢字説明。事前取得が必要 |

ソースの設定を変えずに試す場合も、次のように指定できます。

```sh
make -j4 --output-sync=target POKEDEX_TEXT_STYLE=1
```

かな版へ戻す場合は `POKEDEX_TEXT_STYLE=0` を指定します。コマンドライン指定はそのビルド限りなので、省略するとヘッダーの設定へ戻ります。通常は切り替え時の `make clean` は不要です。

## 説明文の選び方

基本方針は、新しい世代、その中では新しい発売作品を優先し、その種族・フォルムの説明がない場合だけ過去作へさかのぼることです。固定したコーパス内で、次の順に探します。

1. Pokémon LEGENDS Z-A
2. スカーレット・バイオレット
3. Pokémon LEGENDS アルセウス
4. ブリリアントダイヤモンド・シャイニングパール
5. ソード・シールド
6. ウルトラサン・ウルトラムーン
7. オメガルビー・アルファサファイア

同じ作品組にA/Bの説明がある場合は、Aを優先し、Aに有効な説明がなければBを使います。例えばSVはスカーレット、剣盾はソードが優先です。未収録を示す空欄や `[~ 0]` 等は説明文として扱いません。

**エメラルドと内容が異なる説明文にも置き換わります。** 語句の独自翻訳はせず、ルビの除去、全角英数の半角化、空白・改行の調整を行います。フォントにない漢字は、コーパスに明示されたルビがある場合だけその読みへ置換します。今回の採用分では、その読みへの置換は0件です。

### フォルムの保護

全国図鑑番号は内部の `SPECIES_*` の数値と別に取得します。フォルムは同じ全国図鑑番号の中で、メガ・リージョン等の表示名、既存かな説明との一致、同文共有の根拠を確認して対応付けます。

対応が確定できないフォルムには、通常フォルムの説明を推測で割り当てません。従来のかな説明を返します。例えばガラルのヒヒダルマは通常状態とダルマモードを別々に扱います。

現在のmanifestは **基本1,025種族＋458フォルム＝1,483件** を選択し、**88件は既存かな説明へフォールバック**します。アローラのコラッタ・ラッタの旧作個体番号対応や、一部の派生フォルムは未確定です。全件の理由は `tools/data/pokedex_kanji_manifest.json` の `kana_fallback` に記録しています。

| 採用元 | 種族・フォルム件数 |
| --- | ---: |
| LEGENDS Z-A | 584 |
| スカーレット・バイオレット | 543 |
| LEGENDS アルセウス | 120 |
| BDSP | 75 |
| ソード・シールド | 145 |
| USUM | 15 |
| ORAS | 1 |

コーパスの更新を自動追従して説明文を変えることはしません。上記は固定リビジョン内での優先順です。

## 実装と生成物

| ファイル | 役割 |
| --- | --- |
| `include/config/pokemon.h` | コンパイル時の選択 |
| `tools/pokedex_kanji.py` | 取得、対応確認、選択ヘッダーの生成 |
| `tools/data/pokedex_kanji_manifest.json` | 参照作品・qid・行番号・ハッシュ・対応根拠。本文そのものは保存しない |
| `src/data/pokemon/pokedex_text_selected.h` | ローカル生成する選択済み本文。git管理外 |
| `build/generated/pokedex_text/report.json` | 今回選択した設定と件数 |
| `build/generated/pokedex_text/selected.ok` | 生成完了stamp |
| `charmap_kanji.txt` | 既存エンジンと共通の永続ID台帳。git管理対象 |

Makefileの既存の生成段階で本文を確定し、そのあと既存の漢字自動生成を実行してからCの文字列を符号化します。並列makeでもこの順序を維持します。本文が変わらなければ生成ヘッダーの更新時刻は変えません。

かな版では空の選択ヘッダーを生成するため、未選択の漢字説明は漢字検出対象にもROMにも入りません。`make clean` / `make clean-generated` で選択ヘッダーとstampを削除します。永続ID台帳とダウンロードキャッシュは残し、次回makeで選択ヘッダーを再生成します。

ランタイム側では `src/pokemon.c` の `GetSpeciesPokedexDescription()` だけで切り替えます。通常図鑑・HGSS図鑑の両方がこの関数を使用します。既存のspeciesデータ、説明文、ID、セーブ・通信形式、名前・ニックネームには変更を加えません。

漢字版でも、フォールバック用の既存かな説明は保持します。漢字は既存のFC拡張・影付き12px送りを使用し、かな・英字フォントを変更しません。

## 表示幅と容量

本文は最大3行、1行224px以内へ再改行します。漢字12px、かな・句読点7px、ASCII英字8pxの保守的な幅で検査します。画面の横幅240pxに余白を残します。未定義文字、非対応の制御記法、3行に収まらない本文は推測で加工せず、manifest作成時に除外理由を残します。

今回の標準設定・ARMビルドでの実測値です。`.gba` の32MiBパディング後サイズではなく、リンク後の実使用領域を比較しています。

| 項目 | 追加前のかな版 | 漢字版 |
| --- | ---: | ---: |
| ROM実使用量 | 26,486,820バイト | 26,668,772バイト |
| EWRAM | 226,840バイト | 226,840バイト |
| IWRAM | 28,576バイト | 28,576バイト |
| 使用漢字 | 25字 | 1,324字 |
| 漢字画像 | 2,048バイト | 84,992バイト |
| 漢字slot表 | 52バイト | 2,650バイト |

漢字版のROM増加は **181,952バイト**。既存IDを保持したまま1,299字を追加し、上限2,214字に対して890字分が未割当です。選択テーブルは6,292バイトです。本文・ポインター共有やアラインメントを含む総量なので、単純にソースのUTF-8バイト数を足した値ではありません。

ID台帳は削除・再利用しない設計です。かな版へ戻すと不要な漢字画像は消えますが、割当済みIDのslot表は残ります。**かな版でもslot表が2,598バイト増える**点に注意してください。

かな版へ戻して再ビルドしたROM実使用量は26,489,404バイトでした。追加前との差は2,584バイトで、slot表とコード・アラインメントの差を含みます。漢字画像は再び2,048バイト、漢字説明の参照テーブルはリンク対象外です。

### frontier-hackへの統合

上記の容量測定はmaster基盤の値です。frontier-hackは独自の漢字テキストや画像・イベントを含むため、そのままのROM容量にはなりません。

frontier-hackでは、統合前の756字すべてのIDを保持し、図鑑対応に不足する686字だけを未使用IDへ追加しています。台帳は計1,442字、未割当は772字です。独立して増えた台帳なので、masterと同じ漢字でもIDが違う場合があります。別ブランチの符号化済みデータや生成済みフォントを流用せず、それぞれのソースと台帳でmakeしてください。旧25字のIDはどちらでも同じです。

統合後のfrontier-hackのROM実使用量は、かな版25,798,572バイト、漢字版25,939,036バイトでした。同じ統合後ソースでの設定差は140,464バイトで、EWRAM・IWRAM使用量は変わりません。両設定のROMビルド、日本語文字列検査、回帰テスト194件、通信互換性fingerprintの検査に成功しています。ゲーム内の画面巡回確認は含みません。

## 検証

```sh
python3 -m unittest discover -s tools/tests
python3 tools/check_jp_text.py
make -j4 --output-sync=target POKEDEX_TEXT_STYLE=1
make -j4 --output-sync=target POKEDEX_TEXT_STYLE=0
git diff --check
```

新しいテストは `tools/tests/test_pokedex_kanji.py` にあります。最新作品優先、未収録マーカー、内部IDと全国番号の分離、フォルム曖昧時の除外、全採用本文のハッシュ・幅、キャッシュ欠損・破損時の保護、かな版のキャッシュ不要動作、共通getterを実行して両設定の分岐・無効speciesを検証します。

文字列エンジンの既存テストでは、漢字・かな・英数混在、幅計算、描画、プレースホルダー、FC制御、文字列処理、旧25字の画像一致を確認します。ここでの検証はホスト上のC実行・生成物検査・ROMビルドであり、**ゲーム内の全種族・全画面を実際に操作して表示確認したものではありません**。実機での表示・速度も未確認です。

## 参照元の更新

参照元は [abcboy101/poke-corpus](https://github.com/abcboy101/poke-corpus) の固定リビジョン `a022d41cc0e62858bc875a62eb1ba51b1d465826` です。これはゲームのテキストを整理した第三者の資料で、当プロジェクトや公式が作成した翻訳データベースではありません。

通常の利用では `prepare` は不要です。upstreamの種族追加や参照元の更新を行う開発者は、フォルム根拠と差分を再確認したうえで次を実行します。

```sh
python3 tools/pokedex_kanji.py prepare
```

これにはARMプリプロセッサと取得済み全データが必要です。`REVISION` を変えた場合はmanifestの旧ハッシュと新取得データが一致しないため、通常の `fetch` では更新できません。新しい資料を別途取得・確認し、manifestを再作成してから配布してください。自動的なハッシュ緩和は行いません。

コーパス全文・生成本文・ROM・フォント生成物はコミットしません。新規ツールは独立実装で、コーパスのプログラムコードは流用していません。ゲーム本文の権利とコーパスのプログラムのライセンスは区別し、参照したことだけで配布条件を満たすとは扱いません。koden12の既存OFL表示も引き続き保持します。
