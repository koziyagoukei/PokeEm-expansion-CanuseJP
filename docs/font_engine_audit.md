# 日本語フォント調査・段階的実装

## 結論と範囲

2026-10-27、基準コミット `1629c68069` と、この文書を含むブランチのビルドを比較した。基準には25字の漢字表示**試作**を含む。フォント全体を1bpp化した正式な実装は採用していない。計測した描画画像が単純な影生成では一致せず、GBA上の速度・RAMコストも未計測だからである。

参照のないFRLGフォント4シンボルを個別セクションに分け、従来の `--gc-sections` に任せた。通常のフォントと描画処理は変更していない。将来どれかが参照されれば、そのシンボルは再びリンクされる。別途、試作漢字が制御コード除去・比較で消える問題を修正し、試作の漢字画像に影を追加した。漢字の保存・通信は対象外のまま。

## ROM実測

単位はバイト。`.gba` は32 MiBにパディングされるのでファイルサイズではなく、ELFの `__rom_end` と `nm -S`、リンクマップ、シンボルが指すROM中のバイトで比較した。ROMの基点は `0x08000000`。

| 英字グリフ9種 | 294,912 | 294,912 | 0 |
| 日本語グリフ normal/small/short/bold | 81,920 | 81,920 | 0 |
| FRLG日本語グリフ2種 | 32,768 | 0 | -32,768 |
| 漢字試作グリフ | 2,048 | 2,048 | 0 |

| 上記フォント・字幅合計 | 417,792 | 384,000 | -33,792 |
| `StripExtCtrlCodes` と `StringCompareWithoutExtCtrlCodes` | 200 | 340 | +140 |
| `RenderText` / `GetStringWidth` / `DecompressGlyphTile` | 3,840 | 3,840 | 0 |
| ROM実使用領域 | 26,520,388 | 26,486,732 | **-33,656** |
| 既存の文章の漢字置換 | 0 | 0 | 0 |

関数は個別シンボルのサイズであり、フォント描画に関係する全コードの合計ではない。両文字列関数の合計は140バイト増えたが、配置・アラインメント等を含むROM全体の差は136バイト増分に相当する。したがって正味は33,792-136=33,656バイトの減少である。2種のFRLG幅テーブルも各512バイト存在し、最初の推定と異なり**基準ROMに実際に含まれていた**。両グリフデータは日本語normalと同一だった。リンク対象の全オブジェクトで未定義参照を調べ、別途参照を置いた小さなリンク試験では必要な1シンボルのみが復帰した。PNG等の編集用原本は削除していない。

## フォント別基準

`非空` はPNG上で背景以外があるセル数で、実使用グリフ数ではない。セーブ・動的文字列等があるため実使用数と未使用数は未確定。1bpp列は本文を1bppとし右下1pxに単純な影を付けて元画像と完全一致したセル数。全512セルを対象とし、空セルも含む。漢字試作のみ32セル。`推定` は不一致セルを2bppの例外として残し、1セル2バイトの索引を追加した容量で、デコーダ・ヘッダ・パディングを含まない楽観的な下限である。`smol` は各フォント全体を独立して圧縮・展開したホスト実測であり、描画のための展開器・索引・RAMを含まず、そのまま採用できるサイズではない。

## 形式と性能の判断

* **未使用グリフ除去**: 動的参照と文字コードの互換性が確定しないため未実施。FRLGシンボル単位のGCのみ採用。
* **1bppと実行時影**: 上のモデルはPC上のピクセル比較でありGBA用デコーダは未実装。例外やアクセントも含む正確な描画が必要で、単純な影生成では不十分。`12×12`なら連続18バイト/字、行を2バイトに揃えると24バイト/字だが、実行速度・索引・例外を比較できていない。2,000字ではそれぞれ36,000/48,000バイトと索引等が必要。既存フォントの正式移行は保留。
* **既存smol**: 14対象の独立圧縮合計43,116バイトは魅力的だが、必要時に16〜32KiBのフォント全体を展開するか、キャッシュ/ブロック索引を設計する必要がある。展開メモリとスクラッチ、フレーム時間、圧縮ヘッダ・位置合わせを含む純減は未計測。採用しない。
* **描画性能**: フォントGCと影付きPNGは描画ルーチン、グリフ読み取り量、バッファサイズを変えていない。リンク時 EWRAM 226,840バイト、IWRAM 28,576バイトは前後同じ。漢字画像は2bppのままで実行時影生成ではない。1文字/連続描画/メニューのCPUサイクル、動的メモリ、実機性能は測定していない。1bpp・smolの速度やRAMについて性能保証しない。

## 漢字と文字列

試作は `FC 1F xx`、25字、3バイト/字。`{KANJI}` は日本語モード用の `FC 1E`。保存・通信・名前入力形式は変更していない。ローカルに保存された `upstream/master` の `characters.h` は `0x1C` まで使用しており、この参照時点で `1E/1F` の衝突は確認されなかった。将来のupstreamでの予約を保証するものではない。2バイト方式は別途文字列処理や既存コード値の衝突を広く調査する必要があり、現時点ではFC方式を**試作上の第一候補**とする。

`RenderText` と `GetStringWidth`、プレースホルダー展開は試作25字のホストテストを実施。`StringLength` と `StringCopyN` はバイト単位で、後者は漢字途中で切れる。`StringCopyN_Multibyte` / `StringLength_Multibyte` は別の2バイト記号向けで漢字非対応。保存・通信にも関わるので既存の契約を不用意に変更していない。`StringCopyUppercase` は将来のIDによっては本文バイトを変換し得る。これらの呼出し元、改行処理、領域別の幅制限、壊れた制御コード、バンク化と制御バイト衝突を解決するまで、2,000字への拡張や一般文字列への正式採用はしない。IDは既存25字を固定したまま追加する台帳・自動生成を今後設計する。

代表例として `src/data/abilities.h` の186件へ25字で可能な機械的な仮置換を行い、実際のpreprocで符号化した。元3,341バイト、3バイトFCでは3,751バイト（漢字368回、+410）。同じ変換の仮想2バイトでは3,383（+42）、仮想4バイトでは4,119（+778）。EOSを含み、2/4バイトは3バイトの実測からの算術推定。`{KANJI}` 追加分は含まず、日本語デフォルトを前提とする。意味の自然さや全プロジェクトの分布を保証しないため全体への外挿はしない。元テキストは一切変更していない。

小伝馬町12の配布表示とOFL 1.1全文は `kanji_font_poc.md` と `licenses/KH-Dot-OFL.txt` に保持する。ローカルにあるライセンスヘッダには特定のReserved Font Name宣言は見当たらないが、元配布物全体の権利表示を再確認するまでは未確定。予約名が指定されている場合、改変フォントにその名前を使用するにはOFLの条件を満たす必要がある。法的助言ではない。

## 試験と再実行

Ubuntu、arm-none-eabi GCC 14.2.1、mGBA 0.10.5で実施。`make -j4 --output-sync=target`、`tools/check_jp_text.py`、ホストテスト136件は成功。テスト用にROMとセーブを `build/font-engine-eval/` へコピーし、通常会話のプレイヤー名・かな・漢字混在、情報ビューアの通常/小フォント・英数混在、ビューア終了後のフィールド復帰を確認した。影追加前後のPNG比較では、本体ピクセルの変更は0、影は25字すべてに存在する。影あり・なしの画像は同ディレクトリに置いたが `build/` は生成物なのでcleanで消える。戦闘、手持ち、図鑑、技・特性・アイテム画面、色変更、実機、通信・セーブへの漢字入力は画面確認していない。

```sh
make -j4 --output-sync=target
python3 tools/font_engine_audit.py --output build/font-engine-eval/current.json
python3 tools/font_text_sample_audit.py
python3 -m unittest discover -s tools/tests -p 'test_font_engine_audit.py' -v
python3 -m unittest discover -s tools/tests -p 'test_text_language_mode.py' -v
python3 tools/check_jp_text.py
arm-none-eabi-nm -S --size-sort pokeemerald.elf
```

計測にはPillow、ビルド済み `tools/compresSmol/compresSmol` と生成フォントアセットが必要。基準の再現は `1629c68069` を別の作業ツリーへチェックアウトしてビルドする。ROMや抽出バイナリはコミットしない。JSONにはファイルのハッシュと数値を記録するが素材バイトは含まない。基準の `__rom_end` は `0x0994AB44`、変更後は `0x099427CC`。今後のツールチェーンや設定変更ではアラインメント・サイズが変動し得る。
