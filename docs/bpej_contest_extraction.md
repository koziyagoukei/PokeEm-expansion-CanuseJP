# コンテスト・コンディション画像の日本語ROM抽出

## 目的と対象

日本版エメラルド（BPEJ）から、コンテストとコンディション周辺の画像・文字入り画像・パレット・タイルマップをビルド時に抽出します。英語版と同じ画像の取り出しだけでなく、英語で描かれていた見出し等を公式日本語画像へ置き換えることが目的です。

定義元は `tools/data/bpej_contest_manifest.json` です。対象は85件です。

| 分類 | 件数 | 主な内容 |
|---|---:|---|
| コンテスト | 42 | 本編の画面、技部門の文字、審査員、観客、エキサイト、次の順番、結果画面、ランク・部門・通信大会のタイトル、技画面用部門アイコン5種 |
| コンディション・ポケナビ | 31 | 五角形グラフの項目名、検索画面、コンディション・手持ち・検索・部門の見出し、メニュー項目、もどる、アイコン |
| ポロック使用画面 | 12 | コンディション見出し、グラフ、性格欄、ポケモン枠、上下矢印 |

画像に含まれる「コンディション」「かっこよさ」「うつくしさ」「かわいさ」「かしこさ」「たくましさ」、各ランク、「コンテスト」「てもちポケモン」「ポケモンサーチ」等も抽出対象です。周辺の通常文字列は既に `{JPN}` 付きで日本語化されているため、今回は書き換えません。内部定数・部門ID・セーブ形式・コンテストの効果処理も変更しません。

## 一致確認と日本語への置換を区別する

manifestでは、次の2種類を混同しません。

- `verification.kind = identical`：46件。ROMから展開したデータが既存素材と完全にバイト一致します。
- `verification.kind = japanese_ui`：39件。公式日本語UIの対応素材です。英語素材とは意図的に異なるため、`byte_match` は `false` のままです。BPEJの画面コード、スプライト参照テーブル、対応する画面セットと描画サイズを根拠として記録します。

各項目に、ROM offset、圧縮本体を含む切り出しサイズ、圧縮形式、出力先、既存素材、C側のラベルと型、圧縮前後のSHA1、比較元のSHA1、検証方法を記録しています。LZ77本体の長さは `compressed_payload_size` です。`size` にはROM上で確認した4バイト境界までのゼロ埋めも含みます。`u32` 配列に読み込める長さを保ち、ゼロ以外の余剰データは拒否します。

日本語版と英語版で違う部分は、画像だけを単独で混ぜず、次のように対応させています。

- コンテスト結果：日本語版の画像、背景・インターフェース・優勝帯、ランク・部門・タイトルのタイルマップを使います。ランクは8×2タイル、部門と「コンテスト」は5×2タイルとして配置します。
- ポケナビのグラフ：日本語の画像・タイルマップに加え、検索時の9×4タイルの専用オーバーレイも抽出します。英語の共通optionsタイルマップを混ぜません。
- ポロックのグラフ：日本語画像は4000バイトです。固定6656バイトの読み込みをやめ、圧縮ヘッダから取得したサイズで確保・転送します。性格欄は11×4タイルです。
- ポロックのグラフパレット：ポケナビ側と共用だった英語画像のパレットではなく、BPEJの同じ読み込み処理が参照する `0x005BFA4C` を使います。
- 次の順番：日本語版の5タイル・160バイトに合わせ、サブスプライトを32×8と8×8にし、番号の書き込み先をタイル2に合わせます。
- ポケナビ項目：BPEJの13項目×32タイルの画像を使います。既存の項目ID・選択順・スプライト分割・パレット選択は変更しません。
- 技画面の部門アイコン：BPEJの共通シート `0x00D971CC` を展開し、部門5枠だけを切り出します。`SetContestMoveTypeIcons` の部門番号＋18と、SpriteTemplateが参照する実際のアニメーションテーブル `0x005ED3B0` を確認済みです。開始タイルは144・152・160・168・176、各256バイトです。共通パレット96バイトもBPEJとの完全一致を確認しています。

部門アイコンでは `gba_lz77_slice` を使います。manifestには展開元全体のサイズ・SHA1、切り出しオフセット、切り出し後のサイズ・SHA1も記録します。既存の21タイプの画像はそのまま連結し、末尾の部門5枠だけを日本語画像へ替えるため、フェアリー・ステラ等の追加タイプを含む内部ID・アニメーション番号は変えません。既存UI DBのシート全体を `verified` と見なすのではなく、今回対応を確認した5枠だけを登録しています。

LZ77を受け付ける既存の `DecompressDataWithHeader*` 等を利用します。ロード側が非圧縮パレットを期待する項目だけは、抽出時にLZ77を展開してから出力します。不明な形式を推測して処理することはありません。

## ビルド方法

利用者自身が用意した未改変の日本版エメラルドを、プロジェクトルートへ `baserom.gba` として配置します。既存のBPEJ検証定数とROM検証処理を再利用し、サイズ・ゲームコード・SHA1・CRC32を確認します。

```sh
make -j4 --output-sync=target
```

生成物は次だけです。ROM本体とともにGit管理しません。

- `build/extracted_contest/`：85個の抽出ファイル
- `build/generated/bpej_contest_extracted.ok`：manifestと出力状態を検証したstamp

通常のmakeで再抽出・検証を行います。同じ内容ならmtimeを維持するため、Cファイルを不要に再コンパイルしません。抽出ファイルの欠落・破損、customの変更・削除は次のmakeで反映されます。失敗時は該当ラベル・出力パスと、`baserom.gba` の配置案内を表示して停止します。

抽出だけを行う場合や、出力確認には次を使います。

```sh
make extract-bpej-contest
make check-bpej-contest-outputs

python3 tools/extract_bpej_contest.py --print-outputs
python3 tools/extract_bpej_contest.py --dry-run
python3 tools/extract_bpej_contest.py \
  --check --stamp build/generated/bpej_contest_extracted.ok
```

`--print-outputs` はROMを読みません。`--dry-run` はROMと出力データを検証しますが、ファイル・stampを作成しません。`--check` は抽出物・custom・stampの整合性を検査します。

## 元素材とcustom

抽出対象の既存素材は削除済みです。PNG・PAL・BINの86ファイルが対象で、差し替え済みのポケナビ13項目を作る旧合成元PNGも含みます。削除一覧と削除前のサイズ・SHA1はmanifestの `removed_sources` に記録しています。比較時の変換後サイズ・SHA1も各項目に残しています。これらの元ファイルはビルドに不要で、復元する必要はありません。

旧 `gPokenavOptions_Tilemap` は現在使われていない公開ラベルですが、ラベル自体は残し、抽出済み日本語オーバーレイを参照する形にしました。旧合成ルールも削除し、元素材を誤って再生成する経路は残しません。抽出失敗時に元の英語画像へ自動フォールバックすることはありません。graphics全体のinclude pathも変えません。

今回の対象外であるR/S由来の未使用画像、未差し替えの見出し、通常・追加タイプ、別画面の画像は削除していません。`.gitignore` に追加する元ファイルも、実際に削除した対象だけです。

customは `graphics/custom/bpej/contest/` 配下へ、出力先の `build/extracted_contest/` より後ろと同じ相対パスで置きます。例えばグラフ画像は次です。

```text
graphics/custom/bpej/contest/pokenav/condition/graph.4bpp.lz
graphics/custom/bpej/contest/pokenav/condition/graph.bin.lz
graphics/custom/bpej/contest/pokenav/condition/graph.gbapal
```

customがあれば、その項目だけROMより優先します。PNGを直接置く形式ではありません。manifestが指定する非圧縮形式またはGBA LZ77形式・展開サイズを守ってください。画像、タイルマップ、パレットの対応も維持する必要があります。custom使用時も、元のBPEJ ROMと登録ROM範囲の検証は省略しません。

`make clean` で抽出物とstampは消えますが、customは消えません。共通の `clean-assets` でも `graphics/custom/` を除外します。この分類だけを消すには次を使います。

```sh
make clean-bpej-contest-assets
```

## 検証

```sh
python3 -m unittest discover -s tools/tests -v
python3 tools/check_jp_text.py
git diff --check
```

テストでは、英語版とのバイト一致と日本語への意図的な置換の区別、C宣言との対応、ROM・ハッシュ・圧縮形式・パスの検査、4バイト整列、タイルマップの参照範囲、結果タイトル全種類、ポロックの転送量、13個のメニュー項目、部門5アイコンのフレーム・パレット対応、既存21タイプの不変、custom優先・削除、欠落・破損時の検出と復旧を確認します。生成ROMがある場合は、実際にリンクされた主要画像が抽出物と一致することも検査します。

元素材削除後の比較テストは、削除前にバイト比較済みの変換後サイズ・SHA1と、ROMから再展開したバイト列を照合します。削除済みファイルの不在、旧合成ルールの不在も検査します。ビルドとテストのために旧PNGや別の逆アセンブル用フォルダを用意する必要はありません。

タイルマップから再構成した画面で、日本語のグラフ項目、検索時の背景、ポロック背景、通常・通信結果のタイトルとメニュー文字を確認しています。これは実機・エミュレータ上の操作確認とは別です。動的な文字・ポケモン画像を重ねた表示、全ランクのコンテスト進行、通信大会、ポロック使用後の遷移は、ゲーム内での確認対象として残ります。

## 技選択カーソルと動的UIの配置

画像・ハッシュ・背景のタイルマップが正しくても、Cコードで動的に描くタイル番号と形状が英語版のままだと表示が崩れます。技選択矢印に、この不一致が残っていました。

| 項目 | 英語版の描画指定 | BPEJ用の描画指定 |
|---|---|---|
| 矢印のタイル | 55・56・57・58 | 1・2 |
| 左端の列 | 0 | 1 |
| 幅・高さ | 2×2タイル | 1×2タイル |
| 消去 | 左枠11と背景12を2列分描画 | 背景12を1列・2行へ描画 |

BPEJ `asm/contest.s` の `sub_080D8038`（描画、ROM `0x000D8038`）と `sub_080D8064`（消去、`0x000D8064`）を確認し、`src/contest.c` の `DrawMoveSelectArrow` / `EraseMoveSelectArrow` を同じ指定に合わせています。行位置は従来通り `31 + moveIndex * 2` です。左枠の列0と技名の列2以降には書き込みません。

同じ原因の有無を確認するため、削除前の素材をGit履歴から一時取得し、manifestに保存した元の変換後SHA1との一致を確認した上で、動的に参照する各タイルを再比較しました。元画像を通常のソースとして戻す処理ではありません。

| 確認対象 | 主な参照タイル・範囲 | 照合結果 |
|---|---|---|
| アピール・おじゃまのハート | `0x11`～`0x14`、`0x35`・`0x36` | 既存素材とバイト一致 |
| コンディションの星 | `0x34` | 既存素材とバイト一致 |
| 状態マーク5種 | `0x80`～`0x89` と下段 `+0x10` | 既存素材とバイト一致 |
| 結果ゲージ9段階 | `0x4C`～`0x4F`、`0x5B`～`0x5F` | 既存素材とバイト一致 |
| 結果の順位数字 | `0x43`・`0x45`・`0x47`・`0x49` 起点の2×2 | 既存素材とバイト一致 |
| 結果のハート・星 | `0xA2`～`0xA6`、`0xB2`～`0xB4` | 既存素材とバイト一致 |
| エキサイトゲージの更新セル | 上段17～21、下段25～29 | 既存素材とバイト一致 |

これらの番号・ゲージには、矢印と同じ配置不一致は見つかっていません。「つぎのじゅんばん」の数字・ランダム表示、審査員記号、手持ち選択のボール・もどる、キラキラ、ポロックのUP/DOWN、各見出しも、実際に使うフレームの範囲と読み込みサイズを確認します。未使用の旧アニメーションは実行対象のフレームと区別します。

`tools/tests/test_contest_ui_layout.py` では、実際のCカーソル関数と `CopyTileMapEntry` をホスト側でコンパイルし、BPEJの背景タイルマップに対して4つの技枠を描画・消去・上下巡回します。消去後に背景が完全一致すること、左枠・技名領域・他のBGを壊さないことを検査します。ハート等の比較指紋と小型スプライトのフレーム境界も回帰テストに含めます。

矢印の修正前後、エキサイト0～5、次の順番1～4・ランダム、関連アイコン・見出しは静的な画像再構成でも確認しています。実機・エミュレータ内での操作確認とは区別してください。

## 今回含めないもの

- 通常・追加タイプの画像そのもの。BPEJ共通シート全体は差し替えず、今回確認したコンテスト部門5アイコンだけを使います。
- 絵画フレーム、R/S由来の未使用 `graphics/contest/japanese/`、ポケモン本体画像、フォント、鳴き声。
- Expansion独自のコンテストギミックのデータと演出。

これらはBPEJ由来と確認できていない範囲をまとめて置換せず、別の検証単位で扱います。
