# BPEJのきのみ関連アセット抽出

きのみタグ、きのみの大きな画像、バッグ用アイコン、きのみの木、きのみブレンダー、きのみクラッシュのうち、BPEJ内の対応を確定したデータをビルド時に抽出します。

プロジェクトルートに、検証対象の日本版エメラルドROMを `baserom.gba` として配置し、通常どおり実行してください。

```sh
make -j4 --output-sync=target
```

既存のROM検証を再利用し、16MiB・ゲームコードBPEJ・SHA1 `d7cf8f156ba9c455d164e1ea780a6bf1945465c2` の一致を要求します。ROM本体を書き換えません。抽出に別の逆アセンブルプロジェクト、英語版ROM、元のPNG、ネットワーク接続は不要です。

## 対象

| 分野 | 抽出数 | 内容 |
| --- | ---: | --- |
| タグ画面 | 6 | 背景タイル、パレット、背景・タイトルのタイルマップ、味の円、文字パレット |
| きのみ画像 | 86 | BPEJの43種それぞれの48×48画像とパレット |
| ブレンダー | 15 | 中央・外周、各パレット、矢印、得点・粒子、カウントダウン、開始表示等 |
| クラッシュ | 13 | 装置・背景、粒子・数字、各パレット、背景タイルマップ |
| アイテムアイコン | 88 | 43種のきのみときのみジュースの画像・パレット |
| 木の画像 | 32 | 土・芽を含む、ROMと完全一致した木のフレーム画像 |
| **合計** | **240** | **差し替え元191ファイルを削除済み** |

235項目は、既存の変換後データとBPEJのrawデータ、またはLZ77展開後データが全バイト一致します。

次の5項目は英語版と異なるため、JP版の関数・ポインター・対になる素材・確保サイズを確認して画面単位で置き換えています。

- `gBerryCheck_Gfx`: 「からい」「しぶい」「あまい」「にがい」「すっぱい」を含むタグ背景。
- `gBerryTag_Gfx`: JP版タグ背景のタイルマップ。
- `gBerryCheckCircle_Gfx`: JP版の小さい味表示の円。
- `gBerryBlenderStart_Gfx`: 「START」からJP版の「スタート」表示へ。
- `gBerryCrush_Crusher_Gfx`: JP版クラッシュ装置の背景タイル。

かなのタイトル、きのみの名前・説明、サイズ・硬さ等は元からC側の文字列です。これらを画像化したり、今回は本文を自動翻訳したりしません。ポケモン・技・アイテムID、セーブ・通信形式、栽培やミニゲームの判定・報酬にも変更を加えません。

## 対応を確認した根拠

`tools/data/bpej_berry_manifest.json` が抽出元の定義です。各項目に、ラベル・利用ファイル・型・配列形、ROM offset・size・圧縮方式、出力先、元ファイル・変換形式、元データとの比較サイズ・SHA1、ROM範囲と出力のSHA1、関係情報を残しています。

- タグの背景類: 参照用 `pokeemerald-jp/asm/berry_tag_screen.s` の `LoadBerryTagGfx`。ROMの実ポインターを再照合しています。
- きのみ43種: `asm/item_menu_icons.s` の `LoadBerryGfx` が読む `0x0055A7C4` の画像・パレット対テーブル。単に同じ色が見つかったという理由で別用途のパレットを採用しません。
- アイコン: `symbols/bpej/item_icons/symbols.jsonl` の確認済みアイテム別テーブルと、現在の変換データを再照合しています。
- ブレンダーとクラッシュ: 各関数のポインターと完全な画像範囲を確認しています。
- 木: 各フレームを含むrawデータ全体が一意に一致し、BPEJ側のフレーム画像参照も記録しています。
- 元から未使用のブレンダー矢印・パレットも、同じデータ領域の全バイト一致で確認しています。これらの抽出は実ゲームで使われているという主張ではありません。

調査時だけ隣の `pokeemerald-jp` を参照しました。通常の抽出はこのリポジトリのmanifestと `baserom.gba` だけを使います。比較用の変換画像や復元画像はgit管理外の `build/reports/berry/` に置きました。

## データ形式と読み込みの整合性

ROM内で圧縮されている画像・タイルマップは、既存の共通展開入口で読めるGBA LZ77ストリームとして保持します。パレットを `LoadPalette` / `LoadSpritePalette` で読む箇所は、必要に応じてビルド時に展開してrawにします。木の `SpriteFrameImage` 用データもrawのままです。圧縮・非圧縮の取り違えは行いません。

JP版の味の円は32×32です。英語版の64×64 OAMのまま読ませず、32×32へ変更し、中心座標をJP版の `(60,99)`, `(92,99)`, `(124,99)`, `(156,99)`, `(188,99)` に合わせています。タグ以外で使うきのみ本体・回転画像のOAMは変更しません。

ブレンダーの「スタート」は、JP版も元のSpriteSheetと同じ1,024バイト・64×32 OAMです。文字画像だけを縮小したり、手で描き直したりはしていません。

### パレットの読み過ぎを防ぐ

- ブレンダー中央の8bppタイルが使う番号は0〜15です。元の32バイト配列から256バイト読んでいた処理を、`sizeof(sBlenderCenter_Pal)` に合わせました。
- クラッシュの背景パレットは9バンクです。BPEJでは、その直後に土台・エフェクト・数字の3バンクが連続し、まとめて12バンク読んでいます。再配置後の配列の隣接を仮定せず、9＋1＋1＋1バンクを明示的に読みます。読み込む合計384バイトはBPEJの該当範囲と一致します。

## ビルド経路

| パス | 役割 |
| --- | --- |
| `tools/extract_bpej_berry.py` | 分野・型・形式を制限した抽出入口 |
| `tools/data/bpej_berry_manifest.json` | 検証済みの抽出定義 |
| `build/extracted_berry/` | 抽出物。git管理外 |
| `build/generated/bpej_berry_extracted.ok` | 全出力の検査後に作るstamp |
| `graphics/custom/bpej/berry/` | 開発者の独自差し替え。cleanで削除しない |

既存の検証・安全な書き込み・ハッシュ確認・独自素材優先処理を `extract_bpej_contest.py` から再利用します。graphics全体のinclude pathや圧縮エンジンは変更しません。

manifestの240宣言だけを、型とラベルを保った明示的な `INCBIN_*` へ置き換えています。生成段階と対象オブジェクトの依存関係に抽出・検査を追加し、`make -j4` でも抽出が先に終わるようにしています。ファイル欠損・ハッシュ不一致・独自素材の変更も検出し、同じ内容なら出力の更新時刻を保ちます。

個別実行例:

```sh
make extract-bpej-berry
make check-bpej-berry-outputs
python3 tools/extract_bpej_berry.py --print-outputs
python3 tools/extract_bpej_berry.py --dry-run
python3 tools/extract_bpej_berry.py --stamp build/generated/bpej_berry_extracted.ok --check
make clean-bpej-berry-assets
```

`make clean` / `make clean-generated` からも抽出物・stampを消します。独自素材、元ROM、ID台帳は削除しません。出力が足りない場合はパス・ラベル・理由と、`baserom.gba` として日本版ROMを配置する案内を表示します。

## 独自素材への差し替え

`output_path` の `build/extracted_berry/` より下のパスを、そのまま `graphics/custom/bpej/berry/` 以下に配置します。例:

```text
build/extracted_berry/tag/sFontPalette.gbapal
graphics/custom/bpej/berry/tag/sFontPalette.gbapal
```

独自ファイルを優先しますが、元ROMの検証は省略しません。ファイルはmanifestと同じraw/LZ77形式と展開サイズにする必要があります。PNGをこの場所へ直接置く機能はありません。元のROM由来素材を独自素材フォルダーへ移して残す運用もしません。

## 削除と除外

削除済み191ファイルの一覧・削除前SHA1・対応ラベルはmanifestの `removed_sources` にあります。全宣言の置き換え後、旧パス参照がないことと、ファイルが調査後に変更されていないことを確認してから削除しました。

`.gitignore` に加えたのは抽出先と、今回削除した元アセットの個別パスだけです。`graphics/berries/` や全アイコンをまとめてignoreする変更はありません。

後世代のきのみ画像・アイコン、確認できない木の追加画像、戦闘用のきのみ画像、FRLG互換のきのみぶくろは対象外です。未確認データを推測でBPEJの別画像に置き換えません。既存の121宣言に関係するファイルは `retained_sources` に理由を記録して保持しています。

## 検証と残る確認

自動テストは `tools/tests/test_extract_bpej_berry.py` です。全出力のhash・ROM内参照、43組の対応、タイル番号・パレットバンク、OAMと座標、読み込みサイズ、未対応形式の拒否、元画像の削除範囲、欠損・破損時の復旧、独自素材優先・不正ROM時の出力保護を確認します。

実行結果は、抽出単体・`--check`、元画像削除後のmake、`clean-bpej-berry-assets` 後の通常makeによる全240出力の再生成、日本語文字列チェック、回帰テスト208件が成功です。ビルドのROM実使用量は25,956,700バイトでした。この値は作業時のfrontier-hack・漢字図鑑有効設定の結果で、基盤masterとの比較値ではありません。

タグの背景、味の円、スタート文字、クラッシュ背景はROMから静的に復元して比較しました。これはエミュレータ上で全画面・全操作を確認したという意味ではありません。

既存の長いきのみ説明文は今回変更していません。JP版の背景では説明欄の白い領域が176pxですが、現行プロジェクトの文字ウィンドウは長い翻訳用の200px幅を維持しています。説明文が白い領域を越える可能性があるため、本文の再改行・短文化や説明欄の調整は別途必要です。きのみタグ全件、男女別背景、全栽培段階、通信クラッシュ、ブレンダーの全演出はゲーム内での追加確認対象です。
