# Poké Corpusを使った日本語文言の点検

以下の修正数・容量以外の棚卸し件数・初回テスト件数は、master基盤での調査記録です。frontier-hackへの統合では、未使用マップの移動先をmanifestに反映し、トレーナーカードの個数末尾省略と絵画キャプションの詰めた空白を既存仕様として保持しています。この2か所はmanifestの `adaptations` と根拠に記載し、ROM参照41件の検査を維持しています。

## 対象と参照元

[abcboy101/poke-corpus](https://github.com/abcboy101/poke-corpus) のエメラルド用 `qid_msg.txt`、`en_msg.txt`、`ja-Hrkt_msg.txt` を比較資料として使用しました。参照コミットは `a022d41cc0e62858bc875a62eb1ba51b1d465826`。データの記法は同リポジトリの [NOTES.md](https://github.com/abcboy101/poke-corpus/blob/a022d41cc0e62858bc875a62eb1ba51b1d465826/NOTES.md) を参照しています。

コーパス自体は公式の監修資料ではありません。ラベルが同じという理由だけで反映せず、手元の検証済み `baserom.gba`（日本版エメラルド/BPEJ）で本文のバイト列を照合し、現在の用途も確認しています。参照データと全文レポートはgit管理外の `build/` に置き、ゲームの通常ビルドにダウンロード処理を追加していません。コーパスの検索アプリのコードは移植せず、既存のプロジェクト内ツールを使って独立に監査処理を作成しています。

### レイアウトへの配慮

原作の改行をそのまま使うと、Expansionの長い技名・ニックネームが並ぶ行では幅を超える可能性があります。技思い出しの3文は文言を保ち、`\n` / `\l` の位置だけを明示的に調整しています。12字のかな名・16字のかな技名を仮展開し、全グリフを7pxとして過大評価しても各行200px以内となるテストを追加しました。

メールは名前の前に署名ラベルを置く現在の処理を維持しています。「より」を前置して不自然な日本語にするのではなく、表示だけの「なまえ」を使いました。4セルと7文字の名前をそれぞれ7px・8pxで見積もると84pxで、最小88pxの署名領域以内です。署名バッファ32バイトや保存する名前そのものは変更していません。

## 監査ツール

`tools/audit_poke_corpus.py` は**読み取り専用**です。`build/reference/poke-corpus/` に、同じコミットから取得した次の4ファイルを用意して実行します。

- `qid_msg.txt`
- `en_msg.txt`
- `ja-Hrkt_msg.txt`
- `revision.txt`（参照コミットIDを1行で記載）

```sh
python3 tools/audit_poke_corpus.py
```

`build/reports/poke_corpus/comparison.json` に、対象ファイル・ラベル・現文言・参照文言・コーパスID・行番号・参照元コミット・ファイルハッシュ・ROM位置・判定を出力します。

対象は `data/` 配下のラベル付き `.string` と、`src/` 配下の名前付き `_()` 文字列です。現行の配列形式に変わった戦闘メッセージは、ローカル `upstream/master` の同じ内部定数の英語本文がコーパスと一意に一致する場合だけ候補にします。上流参照がない場合、この追加比較は行いません。配列の数字順や曖昧な類似検索で意味を決めません。

条件付きの重複定義、国際通信の別言語名、生成データ、独自追加要素など、すべての表示文字列を網羅するパーサーではありません。コーパスの行数不一致はエラー、同名IDの重複は曖昧として除外します。未収録文、不明な制御コード、参照バイトがBPEJに見つからないものも反映候補から外します。

**注意:** `japanese_difference` は誤訳の確定ではありません。改行、UI位置、文字色、フォント指定や追加世代の仕様が理由で異なることがあります。変数の個数と種類が違う場合は `placeholder_review` に分けています。`matching` も動作確認済みの意味ではなく、指定の正規化後のバイト列が同じという判定です。

## 確認済みの参照manifest

`tools/data/poke_corpus_text_manifest.json` に今回選んだ41定義を保存しています。コーパスIDと参照コミット、BPEJのオフセット・サイズ・SHA256、対象文字列のハッシュ、調整内容を記録した参照情報であり、コーパス本文やROMダンプ一式ではありません。

既存の検証・反映ツールを再利用します。

```sh
python3 tools/sync_bpej_text.py --check --manifest tools/data/poke_corpus_text_manifest.json
```

`--apply` は、確認済みの元文字列が残っている場合に限って反映します。別の翻訳や独自改修が入っている場合は上書きせず停止します。改行の調整、色定数の同義名、音楽IDの定数名への対応はmanifestで明示しています。

他の翻訳を追加するときは、新しいコーパス結果をそのまま一括反映しないでください。参照元の意味、実際に呼ぶ処理、変数、行幅を確認してからmanifestを更新します。

## 残した差異と残件

- 英数字、HP・PP・Lv等の略称、入力キー、クレジット、国際通信向けの別言語名は一律に翻訳しません。
- 原作から変わった技・特性の性能説明、技思い出しの追加変数、短いUI表記、空文字列の用途は維持しています。
- 例として、現在の能力変化処理は第2バッファに変化の程度だけを入れます。原作の文末を含むテンプレートを戻すと文章が欠けるため、そのまま置換していません。対象を巡回する「はりきっている」メッセージの対象変数も原作へ戻していません。
- 文字入力キーの表示だけをかなへ置換すると入力内容との対応が崩れるため、キー配置・入力処理の日本語対応は別作業です。
- 未使用・追加要素・対応未確定の文章も残ります。「英語がすべて消えた」「全ての日本語が正しい」という保証ではありません。

`tools/audit_jp_localization.py` に、プレースホルダー後の英語所有格を見逃さない検査も追加しました。今回の修正後の棚卸しでは、英語・混在候補は **1,402行** です。修正前の1,430行との比較単位は `.string` の断片とC定義であり、43定義という修正数と同じ単位ではありません。

`build/reports/poke_corpus/after/remaining_english.csv` / `.md` に残件一覧を生成しています。候補の大部分はデバッグ表示、FRLG/RS由来データ、国際通信名です。コーパスの照合だけで使用中・未使用を確定していません。
