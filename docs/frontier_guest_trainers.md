# フロンティア7戦目のネームドトレーナー

## 仕様

- タワー・パレス・アリーナ・ファクトリーの、ブレーン戦ではない7戦目にランダム出場する。
- シングル・ダブル、およびタワーのNPCマルチ・通信マルチを対象とする。
- ドーム・チューブ・ピラミッド・バトルテントには追加しない。
- ブレーンの出現条件、シンボル、専用BGMは従来どおり優先する。
- 最初の2枠を指定タイプから選び、残りは既存フロンティアプールから選ぶ。タイプ1・タイプ2の両方を判定する。
- マルチでは各相手が2匹ずつ持つため、各相手の2匹ともその相手の指定タイプになる。
- 既存の種族・持ち物重複制限、メガストーン・Zクリスタル各1匹までの制限、禁止種族設定を引き継ぐ。
- 通常NPCの7戦目にあった「石持ち・禁止級の特定枠への強制選出」より、ネームド戦では指定タイプ2匹を優先する。残りの枠は自由選出とする。
- 既存の周回別個体値補正を維持する。ファクトリーも既存の最終戦用個体値処理を使用する。
- 26候補を等確率で選出する。マルチでフウ・ランのどちらかが選ばれる場合は、2人のペアへ置き換える。

## 表示・互換性

- フウ・ランはシングル・ダブルでも「フウとラン」と既存の2人立ち絵を使う。マルチはフウ・ランの別IDを必ずペアで出し、立ち絵は両方とも既存の2人立ち絵を使う。
- カガリの立ち絵は承認済みのマグマ団女性汎用画像を使う。
- ウシオ・イズミ・ホムラのフィールド画像は対応する団員画像を使う。戦闘立ち絵は既存の各幹部画像を使う。
- リョウヘイのフィールド・戦闘画像は男性エリートトレーナー。
- 通常300人の会話は変更しない。追加ゲスト用に短い共通会話を用意し、フウ・ランの開始会話のみ別にする。
- ゲストIDは `TRAINER_PLAYER` より後ろの別枠。既存の通常NPC・通信レコード・弟子・ブレーンID、SaveBlock、通信データ構造の配置は変更しない。
- バトルビデオ保存時、ゲストIDを弟子配列の添字に誤変換しないよう範囲判定を補う。
- タワー通信マルチでは7戦目のペアをID配列送信前に決定し、受信後はホストの配列をそのまま使う。
- 新IDを理解しない旧ROMとの接続を防ぐため `LINK_COMPAT_VERSION` を10から11へ更新。レイアウト変更がないため `LINK_DATA_LAYOUT_VERSION` は6を維持する。通信する双方を同じ互換版へ更新する必要がある。

## 検証

- `make -j4 --output-sync=target`: 成功。
- `make -j4 --output-sync=target check 'TESTS=Frontier'`: 86項目成功。新規ゲスト10項目を含む。
- 全26候補の2・3・4匹パーティーを、禁止種族許可あり・なしでテスト。指定タイプ2匹と既存の重複・石制限を確認。
- ファクトリーは32種のシードで、相手生成時のタイプ条件とレンタル種族除外を確認。
- マルチのペア、最終2枠以外の不変性、ブレーン優先、全28IDの名前・立ち絵・性別・フィールド画像・会話・リプレイ時の参照を確認。
- `make -j4 --output-sync=target check 'TESTS=Link compatibility'`: 7項目成功。
- 日本語テキスト検査、通信fingerprint検査、`git diff --check`: 成功。
- mGBAの一時セーブで、フウとラン・カガリ・リョウヘイの戦闘立ち絵、名前、技選択画面までの進行を確認。元のセーブデータは保存・変更しない。
- 通信マルチの2台接続、実際に各施設を7戦通して進める操作、バトルビデオの保存・通し再生は未実施。
- 通常ROMのEWRAM使用量は227,472Bで追加前と同じ。
