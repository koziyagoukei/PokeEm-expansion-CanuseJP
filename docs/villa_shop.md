# ミニミニ別荘のBPショップ

## 利用方法

ミニミニ別荘のショップ入口（座標16,7）から入室できます。
カウンターの店員は秘密基地の家具、右側の店員は手持ちポケモンのボール変更を扱います。
家具は全120種類、一律10BPです。購入後は既存の家具所持一覧へ追加されます。
家具を買うだけでは部屋への配置は行いません。
上下でスクロール、左右でページ移動、Aで選択、Bまたは「やめる」で終了します。
購入確認をキャンセルした後や購入後は、選択していた位置へ戻ります。

| ボール | BP |
| --- | ---: |
| モンスター | 1 |
| スーパー・ヒール | 2 |
| ハイパー・プレミア・ネスト | 3 |
| タイマー・クイック・リピート・ネット・ダイブ・ダーク | 5 |
| ゴージャス | 10 |
| レベル・ルアー・ムーン・フレンド・ラブラブ・スピード・ヘビー | 20 |
| ドリーム・ウルトラ・コンペ・サファリ・パーク | 30 |
| マスター | 50 |
| プレシャス | 100 |

## 安全性

- 家具の所持枠不足、BP不足、キャンセルではBPを消費しません。
- ボール変更は手持ちの非タマゴのみ。同じボールなら変更せず、BPを消費しません。
- ボール自体のアイテム所持は不要で、消費もしません。
- 既存のBP・家具所持配列・`MON_DATA_POKEBALL`を使用します。SaveBlockの追加・配置変更はありません。
- 秘密基地、自室、ローカル部屋の家具配置データは変更しません。
- マップは既存グループの末尾へ追加し、既存マップIDを維持します。
- 通信処理、通信バージョン、通常ショップの処理は変更しません。
- 常駐EWRAMの増加は8バイト。一覧用領域・ウィンドウは終了時に解放します。

## 検証

- `make -j4 --output-sync=target`：成功。
- `python3 tools/check_jp_text.py`：成功。
- `make -j4 --output-sync=target check 'TESTS=Villa shop:'`：8件成功。
- 全120種類の家具購入、全27種類のボール価格・変更、BP不足、所持枠不足、同じボール、無効ID、タマゴを自動テストしました。
- ボール変更後のポケモン構造体が、ボールだけを変更した期待値と一致することを確認しました。
- テストランナーには既存の`secret_power.c:7: ASSUME failed`診断が4件出ますが、対象の8件は全てPASS、終了コード0です。
- mGBA 0.10.5コア上の実ROMで、家具一覧・最終項目・購入・手持ち選択・ボール変更・同じボールの再選択・出入口の往復を確認しました。
- 一時RAM上の500BPで、家具購入後490BP、マスターボール変更後440BPを確認しました。ディスク上のセーブは変更していません。
- 実機・スマートフォンでの確認と、保存後のゲーム再起動確認は未実施です。
