# 日本版ROMを参照した文言の整備

## 今回の範囲

プロジェクトルートの `baserom.gba` に配置した日本版エメラルド（BPEJ）を読み、対応を確認できた表示文字列を公式日本語へ近づけています。内部ID、イベント命令、技・特性の性能、セーブ形式、フォント画像は変更していません。

- ROM参照と現在のソースの照合対象: 9,282定義。
- 参照オフセット・バイト列のSHA256・対象ラベルを記録した更新: 986定義。
- このほか、追加機能の未翻訳やUIの操作名も補完翻訳しています。
- 「全件が公式文言と完全一致した」という意味ではありません。BPEJにない追加要素や、対応を確定できない文言は区別しています。

`{JPN}` の付加だけの更新も件数に含みます。生成ヘッダ、フォーム別データ、イベントの複数 `.string` 行などがあるため、ゲーム中の会話数や未翻訳一覧の行数とは一致しません。

## 参照元と安全策

使用するROMのSHA1は `d7cf8f156ba9c455d164e1ea780a6bf1945465c2` です。既存の `tools/check_baserom_jp.py` と同じサイズ・ゲームコード・SHA1で検証します。ROMは読み取り専用です。

隣接する `pokeemerald-jp` の逆アセンブルは、関数、テーブル参照、データ境界を確認する参考として使いました。対応付けには、マップのイベント配置・分岐先、関数が参照するテーブル、元の定数の意味、本文と変数の意味を使っています。名前の似たラベルや、似た文章だけで置き換えていません。

古い英語版の履歴と現在のExpansionでは、種族・技・戦闘メッセージ等の数値IDが一致しない場合があります。現在のIDをそのままBPEJの配列インデックスに流用してはいけません。

既存の `extract_jp_official_text_candidates.py` による候補や古い抽出レポートを、そのまま自動反映しないでください。文字コードと音楽IDなどの重複、旧版と現行のID差、文脈の不一致を別途確認する必要があります。

### そのまま戻していないもの

- Expansionで変更された技・特性の効果説明は、古い仕様の説明へ戻していません。
- 以前整備した短い実用的な技説明、追加世代の名前、独自のヘルプ本文は維持しています。
- 経験値文の3変数化、特性ポップアップ、トレーナーの名前と肩書きの結合などは現在の処理に合わせています。
- `PLAY_SE` の数値IDは現在の名前付き定数へ、旧 `ESCAPE` の矢印は現在の矢印トークンへ対応させています。
- `gText_EmptyString3` は現在の `STRINGID_S` にも使われます。日本語では不要な接尾辞を表示しないため、原作の空白1字を復活させていません。
- 桁合わせ・`CLEAR_TO`・計量単位・複数の変数を組み合わせるUIなど、原作と描画構造が違う文言は一括復元していません。
- BPEJの `れんぞく EXCELLENT`（`0x5CCE27`）など、公式日本語でも英字を使う表記は残します。

## ROM参照manifest

`tools/data/bpej_text_manifest.json` は、確認済みの更新対象を保持します。ROMから無差別に抽出した候補一覧ではありません。

| フィールド | 意味 |
|---|---|
| `file`, `target` | 更新するファイルと、ラベル・配列・フィールド等の選択条件 |
| `rom_offset`, `size`, `sha256` | 終端を含む参照バイト列と、その一致条件 |
| `source_sha256` | 確認時のソース文字列。別の編集があれば上書きを拒否する |
| `provenance` | 関数・テーブル・イベント等の対応根拠 |
| `context` | 通常の文字列と戦闘用変数の区別 |
| `adaptations` | 現在のエンジンに合わせた明示的な置換。推測で変換しない |
| `format` | 通常は終端付き。図鑑の分類名などは固定長ゼロ埋めを明示 |

ROMのバイト列には、かな・制御コード・ボタン・EMOJI・音楽ID等で値の重複があります。長い定義に順に一致させるだけのデコーダは使わず、各制御コードの引数と名前空間を区別します。通常文字、フィールド変数、戦闘変数も分けて復元します。不明な制御コードや英字バンクの曖昧な文字はエラーにします。

### 再検証

WSL/Ubuntu等で、リポジトリルートから実行します。

```sh
python3 tools/sync_bpej_text.py --check
```

これはROMの同一性、各参照のハッシュ、対象文字列の一致を確認するだけで、ソースは変更しません。再ビルドごとに自動復元する仕組みにはしていません。独自翻訳を変更した場合、manifestの再確認が必要です。

確認済みの古い文字列だけを再反映する場合は次の形式です。

```sh
python3 tools/sync_bpej_text.py --apply --report build/reports/bpej_text_changes.json
```

全対象を検査してから書き込みます。参照バイト、ラベル、配列件数、元文字列等が変わった場合は停止し、別の編集を上書きしません。改行コードは保存します。

## 追加機能の補完翻訳

BPEJにない文章を「ROMから復元した公式テキスト」と扱ってはいけません。今回は、きのみの追加成長段階・突然変異・雑草、ぼんぐり、図鑑ナビ、コンテストの追加ギミック、連れ歩き、合体相手の選択、図鑑の時間帯などの英語を日本語に補完しました。操作表示は枠に収まりやすい短い語句にしています。

未使用の弟子会話、スタンプカード、きのみ修正プログラム等の対応未確定文も英文の意味に沿って補完しています。これらをBPEJから復元した公式文とは数えていません。未実装の `ABILITY_AURA_GUARD` は名前をカナ表記にしただけで、説明にも未実装であることを残し、機能を追加していません。

トレーナーヒルの対応未確定の3文も、現在の英文の意味に沿って補完しました。特に `TrainerHill_Entrance_Text_CantWaitToTestTheWaters` は、無関係な文の貼り付けではなく、そのラベルにある「各地の強いトレーナーとの腕試し」を訳しています。

コンテスト説明の英語が残った9分岐は、同じ効果関数の既存日本語分岐をBPEJの説明テーブル `0x560BB4` と照合したうえで流用しました。設定条件・アピール値・効果関数は変更していません。クイズの出題者名 `おねえ` もBPEJの `0x5D3D90` と照合しています。

ダイゴの共闘時の表示名は、生成ヘッダではなく `src/data/battle_partners.party` を変更し、ビルドでヘッダへ反映しています。

## 残件の棚卸し

```sh
python3 tools/audit_jp_localization.py
```

次のUTF-8レポートを、git管理しない `build/reports/jp_localization/` に生成します。

- `inventory.json`: 日本語・英語・混在・記号等の全調査結果。
- `remaining_english.csv`: ファイル、行番号、ラベル、現文言、確認区分。表計算ソフト向けにBOM付き。
- `remaining_english.md`: 件数・ファイル別内訳・詳細。

`src` / `include` / `data` のC文字列とイベント `.string` を走査します。Cの連続文字列は1定義、イベントは `.string` の各行を1件として数えます。生成Cヘッダも含みますが、PNGに焼き込まれた文字や実機の全表示を調べるものではありません。

英語候補には、FRLG/RS由来の追加・未使用文、デバッグ画面、国際通信向けの外国語名、クレジット、文字入力キー、公式の英字略称も含まれます。確認区分は作業の優先順の目安であり、使用中/未使用を保証するものではありません。BPEJに存在しない本文や対応が不明な本文を、似たROM文字列で埋めないでください。

今回の最終棚卸しでは1,426行が候補に残りました。内訳はFRLG/RS等686行、開発用599行、国際通信向けの名前80行、文字入力キー・クレジット等26行、その他35行です。その他には公式の `BDタイム` / `EXCELLENT`、`ARシステム`、`DDラリアット`、ボタン名や単位等も含まれます。これは「ゲーム中に1,426文の未翻訳がある」という意味ではありません。メールの署名にある `From` のように、名前の前後配置が関係して一括置換していない項目も残件として記録しています。

## 検証と残る確認

```sh
python3 -m unittest discover -s tools/tests -v
python3 tools/sync_bpej_text.py --check
python3 tools/check_jp_text.py
make -j4 --output-sync=target
git diff --check
```

ホストテストはデコードの名前空間、変数、制御コード、境界、条件分岐、対象限定、元文字列の変更検出、改行保存、一括検証を確認します。日本語チェックは主にcharmap未定義文字や文字列構文を確認するもので、すべての表示枠の幅・行高を保証しません。

実機/エミュレータでの全会話・全UIの確認は未実施です。特に長い名前・肩書き・アイテム名が入る場合の改行、ナウイおやじの連結文、ユニオンルームの通信進行とカード表示、フロンティアのタッグ会話、戦闘の変数展開はゲーム内での確認が残ります。

git管理対象のゲームソースの最終差分は101ファイル・1,079文字列定義です。文字列を除いた差分比較では、イベント命令、内部定数、構造体フィールド、効果処理の変更はありませんでした。git管理しない共闘データのヘッダは、変更した `.party` ソースからビルド時に生成されます。
