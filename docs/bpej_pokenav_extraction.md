# 日本版ROMからのポケナビ画像抽出

ポケナビの共通画面、ホウエンマップ、エントリーコール、リボン画面の画像・パレット・タイルマップを、利用者が用意した日本版エメラルドROMから抽出します。文字を画像として持つ見出しや地図の説明も日本語版を使用します。

## 対象と削除範囲

今回追加した対象は **91項目**、置換後に削除した元ファイルは **72個** です。同じPNGから画像とパレットを生成していたため、項目数とファイル数は異なります。

| 分類 | 項目数 | 主な対象 |
| --- | ---: | --- |
| 共通UI | 21 | 共通ヘッダー、左見出し、回転するポケナビ、背景、メッセージ枠、リスト矢印 |
| ホウエンマップ | 41 | 地図、拡大用画像、22枚の町タイルマップ、拡大時の日本語説明、主人公アイコン、カーソル、そらをとぶ画面 |
| エントリーコール | 13 | リスト画面、選択カーソル、通話枠、モンスターボール、フィールド通話時のアイコン |
| リボン | 16 | 一覧・詳細画面、小・大リボン画像、各パレット |

全項目のラベル、元ファイル、出力先、ROM offset、圧縮前後のサイズ、SHA1、照合結果は `tools/data/bpej_pokenav_manifest.json` に記録しています。`removed_sources` は削除した72ファイルのパス・サイズ・削除前SHA1です。抽出ツールは削除済みの元ファイルを必要としません。

以下は今回の対象外で、既存の参照経路・素材を維持します。

- FRLG追加のカントー・ナナシマ地図とレッド・リーフのアイコン、計16項目。パレットのバイト列がBPEJ内と偶然一致するものも、画面の出自が異なるため採用していません。
- 独自の地名ボックス `graphics/pokenav/name_box.png`。対応するBPEJ画像を確定できないため残しています。
- 既に `build/extracted_contest/pokenav/` に移行済みのコンディション画面や選択ボタン。今回の91項目と重複しません。
- 人物のトレーナー画像、ポケモン画像、会話本文、地名データ。画像抽出を理由としたテキスト・イベントの書き換えは行いません。

## BPEJ由来の確認

抽出元はルートの `baserom.gba` です。既存のBPEJ検証を共用し、サイズ16,777,216バイト、ゲームコードBPEJ、SHA1 `d7cf8f156ba9c455d164e1ea780a6bf1945465c2` を検査します。ROMは読み取り専用です。

91項目のうち **84項目は、元のビルドで変換した非圧縮データと全バイト一致** します。圧縮方式そのものの違いは許容しますが、展開後のサイズ・SHA1を保存しています。残りの7項目は言語固有の画像・配置で、元の英語画像との一致を主張していません。

| 日本語版固有の差し替え | ROM offset | 展開後サイズ | 出自の根拠 |
| --- | --- | ---: | --- |
| `gPokenavHeader_Gfx` | `0x005EFA00` | 1696 | `asm/pokenav_main_menu.s` の `LoopedTask_InitPokenavMenu` |
| `gPokenavLeftHeaderMatchCall_Gfx` | `0x005F0428` | 2048 | 同ファイルの `LoadLeftHeaderGfxForMenu` が読む見出しテーブル、ポインタ位置 `0x005F1448` |
| `gPokenavLeftHeaderRibbons_Gfx` | `0x005F0598` | 2048 | 同テーブルのポインタ位置 `0x005F1440` |
| `gPokenavLeftHeaderHoennMap_Gfx` | `0x005F08B0` | 3072 | 見出しテーブルと `InitHoennMapHeaderSprites` が読むシート、ポインタ位置 `0x005F1428` |
| `gPokenavMessageBox_Tilemap` | `0x005F1780` | 1280 | `asm/pokenav_unk_2.s` の `sub_081C91BC` |
| `gRegionMapCityZoomText_Gfx` | `0x005F4A98` | 2048 | `asm/pokenav_unk_4.s` の `sub_081CC114` が読むシート、ポインタ位置 `0x005F4D1C` |
| `gPokenavRibbonsSummaryBg_Tilemap` | `0x005F65A8` | 1280 | `asm/pokenav_unk_10.s` の `sub_081D011C` |

上記は隣接する `pokeemerald-jp` の逆アセンブル資産を調査に使用しました。`verification.references` に該当関数・行番号・ROM上のテーブル位置と `data/data.s` の包含範囲を記録しています。ビルド時にはその別リポジトリは必要ありません。

パレットの同一バイト列が複数ある場合は、用途に対応した範囲を選んでいます。例えば共通ヘッダーは `0x005EF9E0`、フィールド通話枠は `0x005D74C8`、回転アイコンは `0x005EFDA8` です。

## 抽出とビルド

```sh
python3 tools/extract_bpej_pokenav.py --dry-run
python3 tools/extract_bpej_pokenav.py --print-outputs
python3 tools/extract_bpej_pokenav.py --stamp build/generated/bpej_pokenav_extracted.ok
python3 tools/extract_bpej_pokenav.py --stamp build/generated/bpej_pokenav_extracted.ok --check
make -j4 --output-sync=target
```

- 抽出先: `build/extracted_pokenav/`、計91ファイル。
- stamp: `build/generated/bpej_pokenav_extracted.ok`。
- `--print-outputs` の各行が生成ファイルの正確なパスです。件数はmanifestの `asset_count` と一致します。
- `--check` は全出力の存在・形式・ハッシュと、指定したstampの状態を検査します。欠落・破損時は該当ファイルとラベルを表示します。
- 抽出時はROM全体のSHA1に加え、各範囲の境界・ハッシュ、LZ77ヘッダー・展開サイズ・末尾paddingを検査します。不明な圧縮形式は拒否します。
- LZ77の画像・タイルマップは圧縮済みのまま、パレットや非圧縮スプライトはrawで出力します。元の `.smol` / `.smolTM` 読み込み箇所も、既存の自動判別付き展開関数でLZ77を処理できます。
- 未使用の `sBlueLightCopy` は `blue_light_copy.4bpp.lz` とし、使用中の `blue_light.4bpp.lz` と出力先を区別しています。

Makefileには対象専用の抽出・確認・クリーン規則と、利用するオブジェクトの依存関係だけを追加しています。graphics全体のinclude pathは変更していません。各C宣言の `INCGFX_*` を、manifestの出力パスを明示した `INCBIN_*` に変更しています。

並列makeでも抽出・全出力検査が利用側のコンパイルに先行します。毎回出力状態を確認し、欠落・破損を修復します。同じバイト列はmtimeを変えず、不要なC再ビルドを避けます。

```sh
make extract-bpej-pokenav
make check-bpej-pokenav-outputs
make clean-bpej-pokenav-assets
```

通常の `make clean` でもこの抽出ディレクトリとstampを削除します。`.gitignore` には抽出先・stamp・今回削除した元ファイルのパスだけを追加し、未移行の素材全体はignoreしません。

## 独自素材の優先

独自素材は `graphics/custom/bpej/pokenav/` に配置できます。manifestの `custom_path` を参照してください。抽出先と同じ相対パス・同じバイナリ形式にすると、ROMからの出力より優先されます。PNGを直接置く形式ではありません。

例: `graphics/custom/bpej/pokenav/left_headers/match_call.4bpp.lz`。

画像の展開後サイズ、タイル順、タイルマップ、対応パレットを維持してください。独自素材もサイズ・圧縮形式を検査し、不正な場合は既存の出力を上書きする前に停止します。この配置場所は `make clean` で削除しません。ROM自体の検証は独自素材使用中も省略しません。

## 配置・読み込みサイズの確認

- 町の拡大説明はBPEJでも64タイル・2048バイトです。現在と同じ32x8スプライト3個、4タイルずつの開始位置、最大開始位置60を使用します。日本語版のコールバック `sub_081CC634` も照合し、現在のCコールバックをホスト上で実行して範囲外参照がないことを検査します。
- 左見出しは64x32スプライト2個の配置を維持します。通常見出しは32タイル進行、地図はズーム状態に応じ32/64タイル進行で、すべて各画像の範囲内です。
- ホウエン地図は8bpp・233タイル、タイルマップは64x64の8bitインデックスです。通常UIの16bitタイルマップとは区別して検査します。
- ホウエン地図のパレットは64バイトです。従来の96バイト固定コピーは配列外を読むため、`RegionMapInfo.regionMapPaletteSize` を追加して各配列の `sizeof` を使用します。FRLG追加地図は従来どおり96バイトのままです。セーブ構造やマップIDは変更しません。
- メニュー説明枠は英語版より左右1タイルずつ狭いため、BPEJのテンプレート `0x005F2834` に合わせ、説明ウィンドウを左4・幅22タイルにします。中央揃えも192px固定ではなく実ウィンドウ幅を使います。
- リボン画面の名前枠も右端が1タイル内側です。BPEJの `0x005F7240` と同じ左14・幅12タイルにし、性別・レベルを実幅内で右揃え、残った幅に名前を描画します。これら2か所は、背景を抽出しただけでは枠線をテキスト用タイルで上書きしてしまうための追従修正です。テストではROM内のテンプレートと現在の定義の一致、ウィンドウが枠の内側だけを使うことも検査します。
- 背景・22枚の町地図のタイル番号とパレットbank、カーソル・ポケナビ・リボンのフレーム範囲を検査します。

## 検証と実機確認

```sh
python3 -m unittest discover -s tools/tests -v
python3 tools/check_jp_text.py
make clean
make -j4 --output-sync=target
git diff --check
```

抽出物への切り替え後にビルドを通し、その後72個の元ファイルを削除してクリーンビルドを行います。ROMを使う自動テストには、展開後データ、生成ROM内の配列、出力欠落・破損の復旧、独自素材の優先、異常なROM・独自素材を渡したときの既存出力保護も含みます。

静的な画像合成はゲーム実行の代替ではありません。エミュレータ・実機での操作確認は別途必要です。

今回の確認結果は、元素材削除後のクリーンビルド成功、枠幅追従修正後の再ビルド成功、全97テスト成功、日本語文字検査成功です。抽出ファイル1個を削除してからの並列makeでも、再抽出・該当オブジェクトの再コンパイル・再リンクを確認しています。以下のゲーム内操作は未実施です。

- ポケナビの開閉、各メニューへの移動と戻る操作。
- ホウエンマップの全体・拡大切り替え、町表示、説明画像の巡回、男女の現在位置アイコン、そらをとぶ。
- エントリーコールのリスト移動・選択・通話・人物確認、フィールドからの通話。
- リボン一覧・詳細、小アイコン・拡大アイコン、種類ごとの色と選択移動。
- 既存のコンディション画面と、今回対象外に残したFRLG追加地域への影響がないこと。
