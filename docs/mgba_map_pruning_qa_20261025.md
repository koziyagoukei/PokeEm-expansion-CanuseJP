## 修正内容

### 1. マップ番号変更後の旧セーブ誤読防止

マップ・レイアウト削減で番号が変わるため、削減前のセーブを従来どおり受理すると、保存された番号が別のマップや範囲外を指す可能性があった。

`include/config/save.h` の `SAVE_FORMAT_SIGNATURE` を `0x46520002` から `0x46520003` に更新した。旧形式を移行せず拒否する。マップ・レイアウトIDの変更も形式更新対象であることをコメントに明記した。

**このROMでは旧形式のセーブを使用できない。** 既存セーブの内容を自動変換する処理は追加していない。

### 2. 拡張セーブの検証漏れ

`src/save.c` の通常スロット用チェックサムを、拡張SaveBlock3を含む4084バイトのペイロード全体へ統一した。従来の検証範囲外にあった合成ポケモン等の破損も検出する。

同一スロットの全セクターが同じ保存世代であること、および保存カウンターと物理スロットが一致することを検証する。読込・トレーナーID由来のオフセット取得時にも、選択した世代の一致を再確認する。特殊領域のチェックサム処理は変更していない。

### 3. 全滅時のナース参照の復元

`tools/mapjson/mapjson.cpp` の削減処理で、削除対象マップの `respawn_npc` が既に `"0"` のとき削除判定が次の項目へ残り、維持対象のナース参照まで消す問題があった。

各 `respawn_map` で判定を更新し、値がゼロの場合を含めて `respawn_npc` ごとに判定を終了するよう修正。`src/data/heal_locations.json` のフロンティア用 `LOCALID_FRONTIER_NURSE` を復元した。他の削除済みマップのナース参照は復元していない。

### 4. 無効な機能の配達員を非表示

ふしぎなおくりもの用領域を無効化した構成でも、配布待ち変数等によって配達員が再表示される経路が残っていた。

`data/scripts/cable_club.inc` の共通表示処理で、`FREE_MYSTERY_GIFT` または `FREE_MYSTERY_EVENT_BUFFERS` が有効なら配達員を必ず非表示にした。将来再有効化できるよう、NPC定義と元の有効時処理は残している。両方のポケモンセンター2Fで確認した。

イベント側の定数参照用に `data/event_scripts.s` へ `config/save.h` のincludeを追加した。既存のマップinclude削減は維持した。条件分岐は当該スクリプトで使用するアセンブラの `.if` とした。

### 5. 日本語版に合わないテストの修正

`test/bag.c` の名前順テストは英語名の固定順を期待していた。日本語表示名を `StringCompare` で比較するよう修正し、数量・詰め直し後の所持内容・空き枠の確認も維持した。製品側のソート処理は変更していない。

- 新規開始の導入が完了し、操作可能状態へ戻る。
- 初期手持ち4匹、きのみ67種類が各999個、大切なもの8種類、PC18箱。

- `SAVE_LINK` と `SAVE_NORMAL` の各保存経路からリセット後にデータを保持。ただし、実際の通信セッションを成立させたテストではない。
- 保存ファイルの両スロット各16セクターで、チェックサム・保存世代・物理スロットの整合性を確認。
- 配達員が両ポケモンセンター2Fで非表示。
- ハブの施設メニューを入力操作で選び、バトルタワー受付へ移動。
- 美術館2Fの初回案内後に操作が戻り、再入場で案内が繰り返されない。
- ハブ、定食屋、風呂、別荘のローカルルーム・店舗、コンテスト受付、タワー受付の7経路について、実際に方向入力で出入口を通り、指定先へ移動。

29マップに直接移動し、マップ表示およびスタートメニューの開閉を確認した。対象はハブ、徘徊公園、定食屋、風呂、別荘と関連2室、フロンティア屋外3区画、コンテスト受付、美術館2フロア、アトリエのあな2フロア、ショップ、センター1F、交換所、ランキング、エニシダ宅、7施設の受付、センター2Fの2種類。

最初のDome受付生成は、待機を含むサンプリングで271エミュレーションフレーム程度を要した。短いQAタイムアウトでは停止と誤判定したが、待機を延ばすと完了して操作へ戻るため、ゲーム側の修正はしていない。

### 確認方法上の注意

GUI用Luaは `build/qa_mgba_20261025_gui/` に保存した。途中のログには、導入会話・美術館の初回案内・PC終了確認・方向転換から歩行までの待機不足によるQA失敗も記録されている。これらは条件・入力・待機を調整して再確認しており、ゲーム本体の不具合として数えていない。

美術館は既存の `UBFIX` が有効であることを確認した。本件のために美術館・コンテスト受付の製品スクリプトは変更していない。

QAセーブには最終箱・合成相手等の人工的な検証データを入れているため、通常プレイ用セーブではない。また、Luaは段階的に再開して確認したものであり、すべてが最初から一括実行できるテストパッケージではない。`build/` の削除でQAログ・画像・コピーROMは失われる。
